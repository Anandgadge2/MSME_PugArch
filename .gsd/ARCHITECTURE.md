## 1. High-Level Architecture Overview

The **MSME Marketplace Portal** is an end-to-end, multi-tenant digital procurement and e-marketplace platform engineered for government, public sector, and private enterprise procurement from Micro, Small, and Medium Enterprises (MSMEs) and Self-Help Groups (SHGs). 

The platform supports the entire 5-stage procurement lifecycle (The Procurement Highway):
1. **Sourcing / Request Generation** (RFQ, RFP, Open Tender, Limited Tender, Rate Contracts, Reverse Auctions, Direct Purchase).
2. **Evaluation & Award** (Technical qualification packet screening, dynamic decrement bidding floor, automated L1/L2 rank generation, price-match counter-offers, formal contract award).
3. **Delivery & GRN** (Purchase Order generation, dispatch advisory, milestone logistics tracking, Goods Received Note generation with OTP/e-sign validation).
4. **Invoicing & Tax Compliance** (GST-compliant B2B e-invoices, multi-line item taxation, automated 3-way matching between PO, GRN, and Invoice).
5. **Settlement & Escrow** (Idempotent escrow payment ledger, 2FA transaction authorizations, milestone disbursements, and automated dispute resolution).

## 2. Core Functional Components

### A. Frontend Architecture (`frontend/src`)
* **`features/rfq/components/ProcurementDetailUnifiedView.tsx`**:
  * Unified single-source-of-truth component orchestrating all procurement types (RFQ, RFP, Open Tender, Limited Tender, Rate Contract, Reverse Auction).
  * Enforces the 5-stage **Procurement Highway**: Stage 1 (Evaluation), Stage 2 (Award & PO), Stage 3 (Delivery & GRN), Stage 4 (Invoicing), Stage 5 (Settlement).
* **`features/reverseAuctions/`**:
  * `ReverseAuctionDetailPage.tsx`: Detailed overview, dynamic decrement rules, real-time leaderboard, and PO generation triggers.
  * `ReverseAuctionLivePage.tsx`: Dynamic countdown clock, real-time live decrement bidding console, competitor rank tracking, and bid submission validator.
  * `hooks/useReverseAuctionRealtime.ts`: Multi-protocol hybrid real-time subscription (Pusher with fallback to local WebSocket and polling).
* **`features/procurementBid/`**:
  * Comprehensive bid preparation, multi-packet technical/financial quotation builder, bid comparison matrix (`BidComparisonPage.tsx`), and ranking/results (`BidResultsPage.tsx`).
* **`components/layout/Navbar.tsx` & `Sidebar.tsx`**:
  * Role-aware navigation (Buyer, Seller, SHG, Admin, Master Admin).
  * Server-Sent Events (SSE) notification listener for real-time unread alerts.
* **`lib/api.ts` & `features/shared/apiClient.ts`**:
  * Unified, resilient HTTP client with transparent CSRF token extraction, automated session token refresh on 401s, and standardized API envelope unwrapping.

### B. Backend Architecture (`backend/src`)
* **`modules/procurementBid/`**:
  * `procurement-bid.service.ts`: Core state machine for procurement lifecycle, technical evaluations, financial openings, L1 ranking calculations, award recommendations, and PO issuances.
  * `procurement-bid.routes.ts`: Validated REST endpoints for creating, managing, evaluating, and awarding tenders.
* **`routes/reverse-auction.routes.ts`**:
  * Live reverse auction creation, seller invitations, dynamic decrement validations, floor scheduling, rank recalculations, award offers, and PO issuance.
* **`routes/marketplace.routes.ts`**:
  * Requirement posting, vendor discovery, category taxonomy, and buyer response aggregations across requirements, bids, and auctions.
* **`middleware/`**:
  * `auth.ts` / `authenticate`: JWT extraction and signature validation.
  * `rbac.ts` / `authorize`: Role-based access control (`buyer`, `seller`, `admin`, `master_admin`, `shg`).
  * `csrf.ts`: Double-submit CSRF cookie guard for mutating HTTP methods (`POST`, `PUT`, `PATCH`, `DELETE`).
  * `rateLimiter.ts`: IP and user-based token bucket rate limiting.
  * `errorHandler.ts` & `safeErrorResponse.ts`: Safe sanitization of error messages to prevent leakage of internal stack traces in production.

## 5. Architectural Conventions & Compliance Standards

* **VPAT / WCAG 2.1 AA Accessibility Standards**:
  * Full keyboard operability on all modals, tabs, dropdowns, and data grids.
  * Form inputs linked with explicit labels, descriptive `aria-invalid` / `aria-describedby` markers.
  * Contrast ratio >= 4.5:1 for standard text and 3:1 for graphic components.
  * Live status transitions announced via `aria-live="polite"` or `role="status"`.
* **Zero Dummy / Mock Data Standard**:
  * Strict policy across the repository: zero synthetic arrays, zero mock fallback metrics, zero simulated percentages. Every number and card reflects authentic database state or explicit zero states (`0`, `₹0.00`).
* **Financial & Cryptographic Defense**:
  * Constant-time comparison on cryptographic signatures and webhook payloads.
  * Idempotency keys enforced on payment allocations and purchase order generation.
